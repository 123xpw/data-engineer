# R2：数据库配置与实例生命周期

修改前定义：允许显式配置容器、卷和回环端口，默认仍兼容现有项目。先检查实例/卷状态，再决定是否创建新凭据。已有实例或存量卷但缺私有配置必须明确失败，不覆盖、不猜密码、不删卷。认证错误和数据库选择错误不能等同于服务启动等待。

通过标准：实际新建一个独立测试实例并写入标记；配置重跑和新目录显式复用配置成功；缺配置、错误密码、不完整配置、端口冲突在十秒内失败（时间是本机测试门槛，不是跨机 SLA），不产生新凭据或破坏实例。删除该测试容器、保留受管卷，缺配置仍拒绝，原配置恢复后标记仍在。现有项目实例版本标记与数据计数保持不变。

只清理本轮创建且所有权标签一致的测试容器/卷；不能删除任何已有数据库。未标记的存量卷不自动接管，需另行核实迁移。本轮不声称远程生产 TLS/多平台均已验证，也不把初始化成功等同于全部业务模块完成。

2026-10-30 Q4 集成后新增验收：新实例可从只有模型变量的 .env 追加数据库凭据，保留模型变量；残缺 MYSQL 配置、已有实例/存量卷缺配置仍失败。Docker 只接收四个 MYSQL 变量，临时 env 文件为 0600 且退出/异常都清理。实际新建和恢复后检查容器环境变量名，DEEPSEEK_API_KEY/Q4_LIVE 不得出现；不输出任何变量值。以假模型密钥夹具验证，绝不把真实密钥送进测试容器。
