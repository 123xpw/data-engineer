# Q1.2 补证实验：执行前冻结口径

承接 reports/q1_2_review.md 的 A/B/C 计划。此次实验不改变生产清洗规则，不预设客户均额排序，也不把数据描述当经业务确认的商品主数据。

## A：限定用途的规则影响账

用途仅为“正向商品购物篮候选”的探索。按以下优先级形成互斥决策：

1. 非常规 StockCode（含空）→ 待确认；不因为格式特殊就判为非商品。
2. 纯数字发票、Quantity > 0、Price > 0、常规编码 → 候选保留；这仍依赖常规编码对应商品的待确认假设。
3. C 前缀、Quantity < 0、Price > 0、常规编码 → 从正向购物篮候选排除，但原始账及净销售分析必须保留，不能视为删除授权。
4. 其他情况 → 待确认。

按原因分列，含每类记录数、数量合计、净额、绝对金额、发票数、原始记录序号示例及全部记录序号摘要。完整记录归属在本地忽略目录输出，不进 Git。特殊编码逐代码保留描述与未确认状态。合格条件是所有原始记录恰好一个去向、金额与数量精确对账、发票按集合并集计数。该账证明过滤的机械影响，不证明业务分类正确。

## B：固定分母与筛选分母

候选规则与 A 的“候选保留”相同。每组每张发票保留原额 N0_i、候选额 N1_i、候选行数。没有候选行的发票为“完全消失”；仍有候选行且 N1_i != N0_i 为“保留但金额变化”；其他为“保留且金额未变”（不保证记录未变）。按精确金额比较，零金额行被去除不会误判为金额变化。

设 N0/N1 为原始/候选净额，D0/D1 为原始/候选发票数。报告原均额 N0/D0、固定分母 N1/D0、变化分母 N1/D1。分解恒等式：

`N1/D1 - N0/D0 = (N1-N0)/D0 + N1*(1/D1-1/D0)`。

用有理数精确验证，展示才舍入；D1=0 时相关项不适用。D0>0 时检查发票三类穷尽且互斥、金额变化可还原原额。如果同发票混合缺失/非缺失，按（组、发票）保留，不把两组计数相加当全局订单。

## C：预定分层与大额影响

在候选规则下按国家、月份分别分层（不临时挑有利组合），每组发票按该层内的明细求和。报告所有层的两组样本数、均值、中位数、P90。分位数采用排序后 `(n-1)*p` 的线性插值。按国家或月份切分的跨层发票单列，行数、净额必须加回全体。

每组金额最高 1% 的发票敏感性：移除 `ceil(n*0.01)` 张；同金额按原始发票字符串升序确定先后；n=0 不移除，n=1 移除后均额不适用。披露实际移除数和金额，不把小样本效果称稳定估计，不删原始文件。对全部组和各分层均报告处理前后结果，缺少任一组标注不能比较，不强填方向。所有比较仅描述当前文件，不做身份或因果推断。

## 验证与本轮结论类型

- 手算样本涵盖零额发票完全消失、仍保留但金额变化、仅删除零价行、跨国/跨月同发票、客户缺失、价格三位小数、1% 取整及并列。
- 验证器用 pandas + 整数最小金额单位，从原始 CSV 另算 A/B、各国/各月分布及分位数，与标准库 Decimal 实验交叉核对；不导入实验的筛选或聚合函数作为答案。
- 数值对账不容许未解释差额；均值/分位数展示与独立计算仅容许 1e-8 绝对误差，精确金额必须一致。
- 任何计算失败先修复；排序无论哪一方向都不算失败。结果只标计算是否通过、业务证据是否充分、规则是否获准采用，三者不合并。新增业务放行仍为待确认，不能用本轮通过数量自动批准。
