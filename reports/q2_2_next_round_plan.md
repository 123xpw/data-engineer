# 下一轮 Q2.2：实施前的范围与否证条件

状态：计划，尚未实施；本文件不记录任何虚构的月度结果。选择此轮是因为已完成原始导入和 Q2.1，而月度分析能先验证后续卖家分析共同依赖的订单粒度、状态、时间和金额口径。

## 进入条件

Q2.1 当前源码的验收必须通过；九表原始字段与分析类型转换须可追溯，不能只有行数与金额总和相同。既有回归失败、输入版本变化或未解释的类型损失阻止扩展。尚无独立业务人员复核、尚未测试并发发布等限制继续保留，不转述为已经解决。

## 预先约定的业务口径

- 月份依据下单时间，不混入送达月份；订单数以订单为单位。订单明细先按订单聚合，再 LEFT JOIN 订单表，避免多商品增加订单权重或无明细订单被丢弃。
- delivered_orders 仅指 delivered；canceled_orders 仅指 canceled，unavailable 等状态留在总订单分母，不悄悄等同 canceled。
- cancel_rate 采用百分数，即 canceled_orders / total_orders × 100，最终展示保留两位小数，并在报告标出单位。题目只写“取消率”，此单位是实施约定，不冒充题目已经明确。
- delivered_gmv 为 delivered 订单各明细 price + freight_value 的精确十进制合计，不连 payments。空金额、已送达但无明细必须先诊断，不能静默填零制造完整成交额。
- avg_delivery_days 按订单等权，以实际送达减下单的秒数 / 86400 保留不足一天的时长；缺实际送达时间不进平均分母，同时单列缺失数及有效分母。负时长须暴露，不自动取绝对值或截成零。
- 缺下单时间不能强行分配月份。先观测真实异常规模，若发现则记录隔离数量及原因，修改口径前说明影响，不用 WHERE 直接隐藏。

## 实验及预期

| 风险 | 预先设计的证据 | 什么结果会否定实现 |
|---|---|---|
| 连接后订单重复计数 | 手算夹具含一单多明细、无明细、同额不同单 | 总订单数或平均送达天数随明细数改变 |
| 状态或月份选错 | delivered/canceled/unavailable 与跨月送达混合夹具 | 取消分母漏其他状态，或归入送达月 |
| 金额公式错误 | 运费非零、同价两明细、取消单带金额 | 漏运费、SUM DISTINCT 丢金额、纳入取消 GMV |
| 时间分母错误 | 送达时间 NULL、半天和两天订单，手算均值 | NULL 当零天、按明细加权或先截天 |
| 参考实现共用同一错误 | SQL 外用原始 CSV 和 Decimal/datetime 按订单复算，每月各指标对齐 | 只能全局合计相等，月份或分母不同仍被接受 |
| 测试缺少辨别力 | 对上述错误逐项做可运行的定向变体 | 错误查询仍通过；语法错误不算有效捕获 |

只有手算反例、真实逐月复算、诊断覆盖和入口/回归均通过，且没有未解释的差异，才允许进入 Q2.3。不是以测试数量达标，也不是宣称所有业务风险归零。若出现新问题，修复其原因并重复受影响的检查；若发现题意歧义，明确保留假设与敏感性结果。
