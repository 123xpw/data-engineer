# Q2.2 实验结束：验收结论与限制

本轮 Q2.2 已完成实施及最终补强验收。当前报告 [ac95458fbee14e6eb673193afa221100](q2_2/acceptance_ac95458fbee14e6eb673193afa221100.json) 状态 passed，绑定当前源码指纹和产物摘要。上一份通过报告 [1b8920feb52145029758ffdbaf8a07b6](q2_2/acceptance_1b8920feb52145029758ffdbaf8a07b6.json) 属于半单位舍入反例加入前的历史，不是当前版本的放行证据。Q2.3–Q2.4 和后续模块尚未完成。

## 验收依据

先按 [实施前验收约定](../q2_sql_analysis/ACCEPTANCE_Q2_2.md) 固定业务口径和手算预期，再实施。真实数据不符合预期时先追查原因；没有更改原始 CSV、没有放宽数值误差、没有用通过项数作为结束条件。

| 需要解决的风险 | 本轮实际检验及结果 |
|---|---|
| 明细连接改变订单权重 | SQL 先聚合到订单；手算多明细、无明细、跨月送达；等额拆分明细不改变指标，同额新订单能增加 GMV |
| 状态和金额口径错误 | 已送达才计 GMV、含运费；取消仅 canceled、分母含所有状态；无 delivered 的月 GMV 为 0、平均天数为 NULL |
| 空时间/异常金额被伪造为零 | 缺送达时间单列分母；缺下单时间、已送达缺明细/金额、负时长阻止正式发布；全部时间为空及空输入另测 |
| 验证器不敏感 | 十种可运行错误均执行后被数值断言拒绝；语法错误不计捕获。独立参考先通过固定手算校准 |
| 手算样本过于整齐、舍入次序不合理 | 真实复算发现偏差后，用 1 秒反例复现；一度全通过后又用 2、2、77 秒复现半单位边界错误。最终先累计整数秒，再一次除法及舍入 |
| 两套结果只在总数上相等 | 原始 CSV/Decimal/datetime 按订单复算，逐月比较七个指标及五个诊断列，25 个月全部相等 |
| 新功能破坏旧模块或入口 | 独立/总入口在外部目录实测，缺输入阻断；Q2.1 故障不阻止独立 Q2.2 查询的控制流测试；当前源码九表/Q2.1/Q1 全链回归通过 |

其中入口隔离的 mock 只证明控制流，SQL 正确性使用真实 MySQL 8.4.13；独立参考没有调用生产聚合函数。最终回归证据为 [f18cb5982ac340b9984fe97b80070776](q2_1/acceptance_f18cb5982ac340b9984fe97b80070776.json)，包含九表原始值和类型值全量比较及 Q1 回归。无新依赖，复用已有锁定依赖安装证明，本轮没有重新部署全新机器。

## 本轮没有在手算通过后结束

- 首次边界失败：[483cf7e61d6744628b7bc1450f116177](q2_2/sql_cases_483cf7e61d6744628b7bc1450f116177.json)。整组缺时间时，负时长计数为 NULL；显式 CASE 修复为已观察负时长数 0，平均时长保留 NULL。
- 手算通过后的真实复算失败：[78fdca9944004ae4876da16d73c60e37](q2_2/acceptance_78fdca9944004ae4876da16d73c60e37.json)。十个月均值受中间除法精度影响。
- 修复前增加一秒反例：[fb1e46fe2f6f4e11a43d00e7c33a8c81](q2_2/sql_cases_fb1e46fe2f6f4e11a43d00e7c33a8c81.json)。旧值 0.000000，固定预期 0.000012。修复分子 Decimal 精度后完整重跑，一度通过，随后继续审查舍入顺序。
- 一度完整通过后的新反例：[0f4f993b8ebd41dfb69cb851c08c4708](q2_2/sql_cases_0f4f993b8ebd41dfb69cb851c08c4708.json)。三单 2、2、77 秒，均值应舍入为 0.000313 天，逐单高精度换算后 AVG 仍返回 0.000312。最终先精确累计整数秒，再除以有效单数 × 86400；历史实数据结果不变，但边界缺陷得到修复。

进一步在真实数据库执行错误连接：99,441 单被 LEFT JOIN 明细扩增为 113,425 行；取消数从 625 变成 706。INNER JOIN 为 112,650 行、取消 542，既漏无明细单又重复多明细单。按订单等权的全局平均 12.558217 天，按明细加权为 12.472246 天；缺时间当零为 12.557176 天。差异小也不能为错误分母辩护。详见 [迭代问题记录](q2_2_iteration_issues.md)。

对同类问题也检查了取消率：临时表构造同月 20,001 单，其中 1 单 canceled，其余 shipped，执行同一生产 SQL，仅替换表名；结果 0.00%，符合精确百分数四舍五入预期。证据 [c166c3b5291949d99b2d5085f0d295f4](q2_2/cancel_precision_probe_c166c3b5291949d99b2d5085f0d295f4.json) 记录了复现实验方法。此处没有发现错误，也不将单个边界成功夸大成所有取消率输入均正确。

## 为什么本轮可以结束、还不能声称什么

预先声明的粒度、状态、公式、分母、精度、异常暴露、入口和回归条件均已有证据；已发现缺陷修复后原反例及真实逐月数据重验一致，没有未解释的比较差异。结束的是本轮范围，不是证明代码绝无缺陷，也不是规定“发现两个问题就结束”。

同一 AI 编写和检查仍有共同假设风险，没有独立业务人员审核。delivered 状态不是经审计收入或退款后净额；本轮也未验证并发发布、断电恢复、跨机安装或性能上限。

下一轮方向及进入条件已写在 [Q2.3 实施前计划](q2_3_next_round_plan.md)，重点转为卖家—订单粒度、跨订单客户、评价去重、取消归属覆盖和排名顺序。不能把当前通过结论直接套到卖家指标。
