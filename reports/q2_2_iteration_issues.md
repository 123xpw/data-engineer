# Q2.2 实验中发现的问题与修复

## 真实数据先否定方便的简化

有 775 个订单没有明细，其中 unavailable 603、canceled 164、created 5、shipped 1、invoiced 2。已送达订单没有缺明细，但有 8 单缺实际送达时间。无明细订单不能用内连接悄悄丢弃；送达时间缺失不能等于零天，也不能导致该订单退出 GMV。

真实错误连接实验：正确订单 99,441、取消 625；直接 LEFT JOIN 明细后 COUNT(*) 得到 113,425，取消行数 706；INNER JOIN 则为 112,650 和 542。这里 542 不仅包含漏掉无明细取消单，也混入多明细重复，不能简单解释为 625−164。订单等权平均送达 12.558217 天，按明细加权则为 12.472246 天。金额聚合前必须先确认粒度，而不是只给 COUNT 加 DISTINCT。

## 整组 NULL 的诊断计数（实际失败）

首次手算/边界运行 sql_cases_483cf7e61d6744628b7bc1450f116177.json 失败于整个月仅有缺送达时间订单。初版 `SUM(status='delivered' AND seconds<0)` 在整组条件均未知时返回 NULL。该诊断应表示已观测负时长的数量 0，平均时长则必须继续保持 NULL。

改为显式 CASE 的 1/0 累计，不能把所有 NULL 不分含义填零。相同反例重跑通过；正式数据未因此被修改。

## 手算通过后，真实逐月复算发现精度错误（实际失败）

acceptance_78fdca9944004ae4876da16d73c60e37.json 在真实逐月比较失败。十个月的平均天数不一致，例如 2016-12 SQL 为 4.693000，独立 Decimal/datetime 结果为 4.693021；其余金额、计数与分母未发现差异。

初版整数秒数除以 86400.000000000000，分母写很多小数并未保证分子的运算精度。原手算 0.5 天和 2 天刚好未暴露问题。随后在修复前新增 1 秒反例：预期六位小数 0.000012，旧 SQL 实际 0.000000，失败报告 sql_cases_fb1e46fe2f6f4e11a43d00e7c33a8c81.json 保留。

修复为分子先 CAST 为 DECIMAL(30,12)，再除、求平均、最终 ROUND。没有放宽误差或改写独立答案。精度修复后逐月全部指标与诊断严格一致，错误连接实验也使用同样足够的中间精度，避免把连接偏差与舍入偏差混在一起。

## 全部通过后继续否证：精确半单位舍入仍失败

完整报告 acceptance_1b8920feb52145029758ffdbaf8a07b6.json 在当时全部条件下通过，真实 25 个月也一致。但归档前进一步检查聚合顺序：逐单换算为天再 AVG，有限精度的误差可能在最终半单位边界累计。先补写条件，再给三单耗时 2、2、77 秒；平均应精确为 27 秒，即 0.0003125 天，六位小数应为 0.000313。

真实 MySQL 返回 0.000312，失败报告 sql_cases_0f4f993b8ebd41dfb69cb851c08c4708.json 保留。这个新失败不表示先前真实数据算错，而是证明当时的真实数据和手算覆盖没有识别该边界。不能把增加小数位当成消除所有聚合舍入错误。

最终改为先 SUM 精确整数秒，再一次除以有效订单数 × 86400，最后 ROUND；NULLIF 分母为零时保持平均时长 NULL。新增半单位反例及原有一秒、整组 NULL、十种错误变体和真实逐月复算全部重跑；最终完整状态以 q2_2_validation.md 所引用的最新报告为准。旧通过报告保留为历史，不改成失败也不继续当当前版本证据。

同类风险还扩查了取消率：先查常量表达式，再实际创建 20,001 个临时合成订单，其中 1 单 canceled，以未修改公式的生产月度 SQL 执行，得到 0.00%，符合精确预期；记录 cancel_precision_probe_c166c3b5291949d99b2d5085f0d295f4.json。这个假设没有发现对应错误，不为了体现“循环找问题”而虚构失败，也不据此声称穷尽所有输入。

## 仍然需要承认的边界

- 已送达状态仅来自数据标签，不能当成已审计收入或扣除退款的结算结果。
- 缺时间填零的全局均值为 12.557176 天，区别不大仍然不应采用：数值差异小不能使错误分母变正确。
- 合成反例与独立参考由同一 AI 编写，仍可能共用业务假设。没有独立人员审批。
- 关键异常会阻止正式查询发布；这不等于已经建立全量数据质量治理或并发发布协议。
- 本轮未新增依赖，复用此前锁定依赖安装证据；当前新代码及 SQL 在现有环境实测，没有宣称重新部署全新机器。
