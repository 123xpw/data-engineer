# 下一轮 Q2.3：卖家分析的实施前方向

状态：计划，尚未实现。只有 Q2.2 当前源码验收及既有回归通过，才进入本轮。选择卖家分析是因为月度订单口径已建立，但它还需要处理跨卖家订单、客户身份和多条评价，不能直接复制月度 SQL 的连接方式。

## 先明确尚未完全定义的口径

- 拟沿用下单时间所属 2017 年、delivered 且含明细运费的 GMV；该选择是承接 Q2.2 的实施约定，并非根 README 已逐项明确。
- 每个卖家只累计自己明细的金额。订单数、取消率先归并到卖家—订单粒度，同一订单的多件商品不能增加分母。跨卖家订单可分别计入每个相关卖家，但平台汇总不能直接相加卖家订单数。
- 去重客户拟使用 customer_unique_id，不能把每单 customer_id 当成跨订单唯一客户。
- 评价先归并到订单后再连接。最新评价与多评价均值可能不同：先检查真实重复、时间并列和差异规模，再声明确定规则，不能直接对 JOIN 后评论行 AVG。
- 延迟率只对实际、预计送达时间均有效的 delivered 订单计算，同时披露缺失分母；取消率以该卖家可归属订单为分母。没有明细的订单无法归属卖家，必须披露这一覆盖限制，不能推测卖家身份。
- 州内 GMV 排名先在全部有资格卖家上计算，再取全国 TOP 20。GMV 并列排名与恰好取 20 行的稳定规则分别说明。

## 预先验收方向

构造同卖家多明细、跨卖家订单、重复评价、同客户跨订单、跨年日期、缺时间、同额卖家并列等手算反例。增加明细但保持卖家订单金额不变，不应改变订单数、客户数、评分权重和延迟率；新增同客户订单会增加订单数，但不增加去重客户数。

用原始 CSV 以卖家—订单集合、客户集合、独立评价选择与 Decimal 复算所有合格卖家，再比较 TOP 20 和全部州内排名，而不只验证前 20 的总 GMV。对重复连接、错误客户键、先 TOP 20 再排名等可运行错误检查断言敏感性。

任何无法解释的数值差异、覆盖范围变化或评价规则歧义，都应先记录并处理；不得用增加测试数量代替确定业务口径。通过才允许进入 Q2.4 的正确性与性能实验，不能提前宣称优化收益。
