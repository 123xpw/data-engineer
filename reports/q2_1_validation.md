## 真实结果与题目差异

商品表共有 32,951 个商品。按精确类别名匹配，pc_gamer 有 3 个商品、portateis_cozinha_e_preparadores_de_alimentos 有 10 个商品，没有翻译行；共两类、13 个商品。另有 610 个商品原始类别为空，不能命名成第三个“未翻译类别”。原始翻译表 71 行，独立 CSV 检查未发现空字符串或全普通空格英文；本次“有映射但没有有效英文”的类别及商品数均为 0。这不排除其他 Unicode 空白或语义错误。

模块 README 第 26 行的评分表写“3 个未翻译的类别”；根 README 的任务则要求查缺口，并给三种治理方案。数据结果与治理方案数量分开呈现，原题保留，不修改数据迎合预期。

评论表 review_id 的额外出现为 814 条，order_id 的额外出现为 551 条；地理邮编的额外出现为 981,148 条。“额外出现”指总行数减不同值数，不是重复组数，也不等同于应删除的记录数。核验的六组关联孤儿行数为 0，但没有因此推断评论唯一或连接不会扩增。

## 为什么没有在第一次通过就结束

1. 首次 SQL 反例失败：全普通空格英文被当成有效翻译。修复判断条件，失败记录 [1a8f598741984b379e2d63083c0b153c](q2_1/sql_cases_1a8f598741984b379e2d63083c0b153c.json) 保留。
2. 首次全量验收失败：独立参考读取器遗漏 UTF-8 BOM，发生 KeyError；这是验证器错误，未更改 CSV。失败记录 [6616b53464d24b3eb3981ed29bf9a297](q2_1/acceptance_6616b53464d24b3eb3981ed29bf9a297.json) 保留。
3. 修复后完整验收 [1497bb83a17e42399cd336123b97b32e](q2_1/acceptance_1497bb83a17e42399cd336123b97b32e.json) 通过，但继续审查发现分析视图的汇总检查不足。真实 MySQL 合成实验把日期后移一天、或交换两行金额，旧行数/空值/金额总和条件均通过，逐记录比较则拒绝；正确对照通过。实验 [e2c5f187d53941cd91b09f8383374929](q2_1/typed_blindspot_e2c5f187d53941cd91b09f8383374929.json) 不改正式数据，也不表示生产代码曾有这两个错误。
4. 在真实全量分析视图加入逐记录比较后，再次运行完整验收及回归，得到本文首段的当前报告。旧通过记录没有被删除或改成“其实失败”。
