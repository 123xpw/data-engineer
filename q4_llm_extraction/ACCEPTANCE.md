# Q4 分轮验收契约（实施前冻结，2026-10-30）

## R1：无外部凭据也能验收的工程闭环

1. 冻结 CSV 以 SHA256 校验，评分 <=3 的每一来源行恰有一条输出，保留 source_row/order_id/review_id；不得按重复 review_id 去重。空白无问题文本、严格白名单的泛化短语、需模型判断的文本三路分开。未处理必须 partial/待处理，绝不能当成无问题。
2. 模型结果严格检查 JSON 类型、有限数字、范围、枚举、完整且唯一的来源 ID；每条葡萄牙语证据必须是对应原 message 的非空连续子串，英文译文非空。JSON 格式与引文出现不能认证类别、否定语义、翻译或严重程度正确。
3. 每次请求先持久化预算预留，单一账本加锁，不自动重试；中断/超时无用量时保留最坏费用，不当作免费。不允许重新开账本静默绕过累计预算。相同输入/提示/服务配置恢复可复用有效响应；价格、模型、提示变更后不能复用旧结论。总上限 <=3 USD，单次运行 <=2400 秒。价格与上下文上界必须先经服务商文档核实；本地算法不能保证错误报价下的真实账单。
4. 预设反例：错 ID/重复/少行、引用另一评价、否定句仍含关键词、NaN、bool 冒充数字、错误枚举、截断、缺 usage、超时、中断后重跑、低预算。手算的计费夹具与假响应只证明本地控制逻辑，不能称真实 API 或账单证据。
5. 全量真实输入以无网络模式生成逐行路由及未处理状态，另用 csv/Counter 独立复算数量、来源 ID 和空白分布。生成可复现的 30 条盲标任务，人工标签为空；无人工标签时拒绝计算准确率。该样本只能描述其覆盖范围，不自动外推全量。

R1 扩样修复验收补充（首次小样本测试后、修复前）：先处理一条再扩大到四条/更改批大小，前一条不得再次付费；已中断/计费不明的行也不能因批次边界变化被重新发送。用进程休眠夹具核验墙钟终止，不以 requests 的 read timeout 自称总时限证明。加入变异实验，故意移除证据校验、预算占用、恢复缓存，预设反例必须能检出。

DeepSeek 适配验收：按当前官方协议发送 max_tokens 与 thinking.disabled，不发送 max_completion_tokens；stop 但空内容仍拒绝。DEEPSEEK_API_KEY 仅用于官方端点。按官方峰时/缓存未命中价预留与占用，usage 折算只记费用上界，不伪称已核实账单；实际费用字段未对账必须 null。默认配置和真实调用输入摘要需绑定清单。

R1 通过只表示工程流程具备继续实测的条件；完整 Q4 仍 pending。验收脚本需保存当前源码/输入摘要、运行编号、反例明细及限制。

## R2：有服务后的真实小样本与全量运行

首轮真实 4 行在引文大小写处失败（用量已计费），新增修复契约：只允许对“唯一、仅大小写差异”的原文连续区间恢复原始字面，并保留模型原引文/偏移/修复记录；不修改词语、标点、否定关系，歧义或无匹配仍拒绝。严格最终校验不能关闭。新增最多三路有界并发，账本更新串行加锁，预算暂被在途请求占用时等待结算，不重复生成；已知验证失败隔离该批，未知计费/服务边界错误停止扩大。缓存重放不应在四十分钟后被错误判定为超时：时间依据实际调用结束记录与本次运行耗时，而非读缓存当天的日期。

64 条实测批 8/三路外推耗时不足以覆盖剩余全量，下一轮扩大为批 16/最多四路；仍由同一账本上限决定实际在途数。先处理 128 条（复用已验证 64 条）验收预算等待、有效行覆盖与吞吐，再决定全量。不能用改变批大小重发成功行，也不能忽略首轮失败的用量与时间。

128 条通过后计时口径纠错：题目是 pipeline 时长限制，先前自加的“首次试验起连续墙钟四十分钟”把研发、人工分析和暂停也计入，是过度约束。本轮按每次实际完整执行 <=2400 秒验收，跨轮墙钟跨度仍记录，累计费用继续覆盖所有失败/试运行。不得把跨度改名为生产耗时；过期缓存/暂停后仍可恢复，单次请求受本次剩余墙钟限约束。验证该差异后再运行全量，不声称该解释获得出题方确认。

真实失败批次修复验收：模型会替换冠词、补重音或产生无问题但 actionable=true，这些仍拒绝。只有整批来源 ID 集合准确时才能逐行验证并缓存其中有效记录；原始响应不覆盖，失败行保留 pending。修复脚本只选择已报告用量且本版本仍无有效结果的行，每行最多一次显式修复生成（独立 request_id、同一预算），不重发未知计费。脚本需以固定混合好/坏行、重复挽救不重复计数、修复不重复请求的夹具通过后再用于真实数据；尚未有效的行不称完成。

批修复后仍有一条来源 44556 串用了同批 47809 的 Porto 引文，因此新增最后一级“单条隔离”实验：保持模型/主提示和校验不变，仅移除同批其他评价。每行最多主处理、批修复、单条隔离三个生成阶段，所有费用累计；单条仍失败必须 pending，不无限重试。此例隔离通过不证明批间污染普遍消失；最终仍需全量逐条来源校验和真人语义评估。

先核实服务端点、模型、价格版本/币种和输出/上下文上界，做小样本，核对原始 request_id/usage 与账单。未报告用量、超过预留上界或结构/引文错误必须停止并暴露；不自动换模型、涨预算或隐式重试。小样本通过后在相同累计账本内扩大，覆盖全部低分来源行，elapsed <=2400 秒，服务实计/保守占用均 <=3 USD，所有需模型记录有效或明确未完成。

## R3：语义与交付

30 条随机盲标由真人填写，记录标注人、时间、歧义与仲裁；规则也参与评估。报告类别集合 precision/recall/F1、无问题 exact-match、引文/翻译/严重度/可行动性检查，逐条展示差异；缺少预测或标签拒绝。30 条估计有抽样误差，不能宣称总体高准确率。最终 Q4 通过需真实全量、费用/时长、人工结果和当前默认入口绑定证据；R1 假响应不抵消 R2/R3 缺项。
