# Q2.2 实施前验收约定

继承 reports/q2_2_next_round_plan.md，不改变冻结数据。范围仅月度成交分析，不实施卖家分析或性能优化。上一轮已经声明的订单粒度、下单月份、含运费 GMV、百分数取消率、有效送达分母继续适用。

初查真实数据有 775 单无明细（含 164 单 canceled），8 单 delivered 缺实际送达时间；这些是观测，不作为写死答案。后续须用独立原始 CSV 复算验证。订单和已送达 GMV不因缺送达时间而删除；平均天数排除缺时间，披露有效订单数和缺失数。时长按秒/86400，最终四舍五入到六位小数，取消率为百分数、两位小数，金额精确 Decimal。

## 实施前固定反例

- 一月六单：A delivered、0.5 天、两条同额明细各 10+2；B delivered、2 天、一条 20+4；C delivered、送达 NULL、一条 5+1；D canceled 无明细；E unavailable 无明细；F shipped 一条 100+10。应得订单 6、送达 3、取消 1、取消率 16.67%、GMV 54、有效时长 2 单、平均 1.25 天。A 月末下单、次月送达，仍归一月。
- 二月只有一条 canceled 订单，GMV 0、平均时长 NULL。另测空输入、缺下单时间、已送达无明细/金额缺失、负时长；不能以零替代未知金额。缺下单时间保留 NULL 月份诊断组，正式运行拒绝未解释的关键异常。
- 将一条明细拆成两条且金额和运费之和不变，订单指标和 GMV不变；新增一单同额订单则 GMV必须增加。此变换不能与错误的 SUM DISTINCT 混淆。
- 手算预期在 SQL 实施前固定；真实 MySQL 执行，不能用 SQLite 或仅 mock。

## 验证器也要被检验

在临时表上执行可运行错误：内连接漏订单、按明细放大、漏运费、SUM DISTINCT、纳入非 delivered GMV、取消分母只算部分状态、把 unavailable 当取消、按送达月、NULL 时长填零、截断整天。需看到明确数值断言拒绝，语法/连接失败不计捕获。若某错误通过，检查验证器盲区，不直接删掉该错误实验。

真实输出按每月所有指标及诊断分母与标准库 CSV/Decimal/datetime 独立实现对齐；全局金额相同不能替代逐月检查。补充直接连接的真实偏差和缺时间填零的敏感性，说明实际风险而不只依赖合成例。

独立入口、总入口、缺输入阻断、已有 Q2.1/Q1 回归需通过；保存源码指纹和产物摘要，无新依赖可复用锁定依赖安装证明。通过后仅允许进入 Q2.3 实施，不认证业务语义、跨机部署、并发恢复或全项目完成。

真实逐月复算首次发现平均时长不一致后，新增精度反例（修复前声明）：单个订单耗时 1 秒，六位小数应为 0.000012 天。不能把 SQL 的中间舍入当作允许误差；先验证旧 SQL 被此例拒绝，再修复中间精度。原手算半天和整天不能覆盖这个问题。

完整验收通过后、归档前继续补充舍入顺序实验：三单 2、2、77 秒，平均 27 秒，即 0.0003125 天，六位应为 0.000313。先声明此精确预期，再观察“逐单换算天后平均”是否受到累计舍入影响；若失败必须修正聚合顺序，不能删除此例。
