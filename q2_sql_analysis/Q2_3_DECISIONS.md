# Q2.3 决策与面试追问

本轮针对题目没有明确的口径作可复现假设，不能称为业务唯一真值。

- GMV 继承 Q2.2 已送达且含运费的定义；如果改为全部状态含运费，会得到另一种“下单金额”榜。取消率分母仍包含可归属取消订单，否则会恒为零。
- customer_id 是订单关联键，customer_unique_id 才用于跨订单去重；不要把两种键都叫客户数。
- 商品先聚合到卖家/订单，防止一单多商品放大订单计数和评分权重。多卖家订单对每位卖家各算一次，卖家订单数之和不能冒充平台订单数。
- 订单有多条评价。按创建、回答、review_id、来源行降序选一条，只保证重跑稳定。不能证明这是更正关系或最终意见；报告须公开最早/最新/每单均分的敏感性。
- 未知实际送达时间退出延迟率分母并披露；无有效记录返回 NULL，不能填零说“没有延迟”。物流时间与评价为订单级共享，不能推断具体卖家责任。
- TOP20 恰好选 20 名，GMV 并列按 seller_id 升序决定边界；州内使用 RANK 并列跳号。若业务想包含边界全部并列者，应另改契约，结果可能超过 20 名。

面试手算：同买家两笔订单，一笔多商品、多卖家，并有两条不同评分；说明三种粒度为何产生不同均值。解释 522 张无明细订单、61 张无明细取消单为何不能被分给某个卖家。解释为何“先取平台 TOP20，再算州排名”在相同 GMV 排序下可能数值相同，因此不能假报变异捕获。

已知边界：此轮正式接入独立 CLI 和 run_all 的 q2.3 选择器；默认 Q2 与整项目门槛待下一轮整合。旧门槛对应的源码指纹会失效，应重跑或扩展，不能继续引用历史 passed 作为当前整项目证据。
