# Q2.4 正式交付前的验收范围

本轮已做原型及只读计划预查；以下作为正式发布前的冻结标准，不把它伪称为早于全部原型实验的文档。

1. 原题条件保持 delivered、下单 >= 2017-01-01、LOWER(city) 含 sao，包含 2018；不偷偷改成只 2017、精确城市或去重音。固定反例原 SQL 为订单 2/金额 100/评分 3.2，按订单修正为订单 2/金额 70/评分 4.5。
2. 等价提速版必须与原查询全部州全部列相同；保留原查询的统计偏差，仅用于性能对照。业务修正版与原始 CSV 独立复算全部州一致，差异按金额扩增及评分粒度解释。
3. 正式报告至少三个性能问题、候选 SQL、索引/模型建议、当前真实 EXPLAIN；估计行数与实际扫描行数分开，不编造 100 倍数据性能。
4. 性能在其他验收结束、无项目导入的条件下测量。同连接、同批次、一次暖机不计入、三轮交替顺序，记录实际耗时与异常；90 秒服务端超时只记为超时，不报假速度倍数。只比较原始与等价版的纯优化倍数。业务修正速度另列，因为结果语义已经改变。
5. 发布 CLI/默认入口产物及当前门槛后，才将 Q2.4 标为通过；新代码依赖和源码范围必须对应证据。仅计划预查或手算通过不代表正式交付完成。

实验限制：固定冻结版本的原始键、金额、日期字符串经过既有导入验证；直接使用原始键优化不应照搬到未验证任意输入。所有评分治理选择和未知金额都应公开，不能以性能为由吞掉异常。

正式实现前结论：性能实测未证明候选加速，验收允许如实记录未改善；不得为通过而编造速度倍数。原查询、等价候选与修正版 SQL 必须与已计时原型完全一致。正式默认 Q2 应包含四题且 passed，Q3–Q5 仍禁止完整提交。
