# Q2.3 修改前的口径与验收契约

范围：先交付独立 SQL、独立 CLI 与 `--stage q2.3`；当前全项目门槛仍须扩展，不能因本题局部通过宣称全项目可提交。

口径：2017 年按下单时间半开区间；卖家订单由明细归属，每个卖家/订单先聚合。GMV 沿用 Q2.2：仅 delivered 的 price+freight；order_count、cancel_rate 分母包含所有可归属状态。客户按 customer_unique_id 去重。评分每订单仅取一个评价：创建时间降序、回答时间降序、review_id 降序、来源行降序；这是确定性治理选择，不能证明最新记录就是权威意见。每卖家订单等权。延迟仅在 delivered 且实际/预计日期齐全时计入分母；缺时间数量公开。州内 RANK 在全部有 2017 订单的卖家上计算，再选全平台 GMV TOP20；并列以 seller_id 稳定选取，恰好 20 名。

通过条件：
1. 手算样例覆盖多商品、多卖家、重复评价、同客户跨订单、取消、缺日期、零 GMV、州内并列和平台截断；真实 MySQL 与固定预期一致。
2. 原始 CSV 独立字典/Decimal/datetime 复算全部卖家，逐列比较 TOP20；订单和金额守恒及缺失归属单独披露，不能只核对总和。
3. 指定错误 SQL（省略运费、评价直连、客户使用 customer_id、把州内排名误写为全平台排名）需命中具体数值差异；运行错误不得算捕获。
4. 最新/最早/均分评价选择的敏感性实测，承认业务歧义；不因某方案通过数值测试而称语义唯一正确。
5. 独立 CLI 与总入口本题结果一致，失败时清单拒绝旧产物；已有模块当前源码回归通过。不同算法仍由同一 AI 编写，不等于另一位人员审核。

实施前修订：同一 GMV 排序下，平台 TOP20 已包含入选者全部更高 GMV 的竞争者；先截断再州排名可能得到相同入选结果，不能将其设为必捕获变异。仍在实现上保留先完整排名的明确语义，数值反例改为错误的全平台排名。
