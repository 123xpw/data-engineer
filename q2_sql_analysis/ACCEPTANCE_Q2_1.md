# Q2 导入与 Q2.1：实施前验收约定

本轮不实施 Q2.2–Q2.4。数据库必须为真实 MySQL 8.0+，记录实际版本；不能以 SQLite 或 mock 查询结果替代。输入仍为冻结的 Kaggle Olist v2 九张 CSV。

## 导入需要证明什么

- 保留原始文本及逻辑记录序号，原文件不修改。原始暂存层所有源字段按字符串保存，空字符串不擅自变 NULL；分析层显式转换数值、日期及缺失。标识符、邮编前导零、葡语重音、换行及尾空格不得静默改变。
- 每表导入后按记录序号取回全部字段，由独立读取路径逐行比较原始 CSV，而非只验行数。金额另做 Decimal 合计对账；失败、SQL 警告、截断或非法转换不能伪装成功。
- 不预设 reviews.review_id 或地理邮编唯一。先用真实数据核验九表候选键、明细粒度和关联。若加业务键会丢行，保留来源行键并说明；不使用 IGNORE/REPLACE 掩盖重复。
- 本项目使用独立数据库及受控本地实例。可重跑且不重复累计；失败时不把半导入结果当可用版本，不修改其他数据库。凭据不写 Git、日志或报告。

## Q2.1 语义与反例

- 原始类别为空、存在类别但无映射、映射存在但英文为空，分别报告。主答案输出有名但没有有效英文对照的类别及商品数；空类别另列，不能为满足“3 个”而把 NULL 当类别名称。
- 使用不放大商品数的反连接；翻译表若存在重复映射，不能因 JOIN 使商品数翻倍。排序与比较按显式二进制、区分大小写及尾空格的口径；是否归一化是另一项有损决策。
- 在真实 MySQL 临时测试表执行手算反例：已翻译、无映射、空/NULL 类别、空/NULL 英文、重复翻译、大小写/尾空格差异。测试数据明确为合成，不混入正式表。
- 对真实 SQL 结果用标准库 CSV/集合/Counter 独立复算。结果以数据为准，不写死“必须三类”。分别列出三种补译方案及利弊，AI 建议不能未经核对直接作为正确标签。

补充明确空白口径：有效英文检查会忽略其两端普通空格，但不改写原始值；全普通空格不算有效翻译。类别名保持精确比较，不执行 TRIM。制表符、非断行空格等其他 Unicode 空白不在本轮自动规范化范围，需另作质量检查。

## 本轮放行边界

补充验收（在新实验前声明）：行数、NULL 数和金额合计不变仍可能存在日期偏移或金额归属错误。以真实 MySQL 合成临时表构造这两种可运行错误，要求旧汇总条件保持相等而新增逐记录检查拒绝，正确对照必须通过。真实九表分析视图再按来源行逐字段、逐类型与独立 Decimal/datetime 转换核对，不只核对原始字符串层。

首次导入、重跑、九表全字段往返、粒度/关系检查、SQL 反例和真实结果交叉核对均需有证据；新依赖须补干净环境安装证明。通过只表示本轮导入与题目查询按明示口径完成，不代表全部数据业务正确。后续月度/卖家分析必须再检查连接扩增、订单状态和分母。
