# 验收器本身的审查：提前验收标准

基线 9b20de1。只读构造的四类损坏报告已发现旧门槛会错误放行：总状态失败但子阶段全绿、重复阶段中前项失败被后项覆盖、缺少 Q3 三态检查但头部 passed、没有检查且只引用无关文件。真实业务产物和通过报告未被改写。

## 本轮必须通过

1. 完整入口只能接受退出 0、总状态 passed、九个唯一必答阶段全通过；Q2 必须有五个唯一子阶段全通过。缺项、重复、额外阶段、partial 或父子状态矛盾均拒绝。
2. 各程序模块的验收报告必须符合预先列明的检查名称和必需产物集合；检查不得缺项、重复、含失败或用非布尔值表示通过。只有 passed 标头、无关文件或空产物集合不能放行。
3. 发布入口与提交清单共用相同的程序模块证据规则，同时核对当前源码、产物字节及限定范围。缺失/损坏/越界的证据按未完成记录，不能丢失其他未完成原因。
4. 先让新增拒绝用例在旧实现上失败，修复后全部通过；用实际通过报告做正控制，内存/临时副本做损坏控制，不修改真实报告来凑结果。
5. 冻结源码后重新执行当前全部程序回归与完整入口；Q4 仅使用已有真实响应缓存，禁止新增请求。完整提交继续拒绝尚未具备的人审、独立账单、原文日志及最终发布证据。
6. 当前源码另做全新虚拟环境、锁定安装及空缓存数据下载验证，明确数据库是否复用、Q4 是否使用无网络分流；环境/数据验证不能冒充全新模型付费生成或真实语义评估。若失败，保留实际失败并修复后再运行。
7. 最终列明题目必交要求与增强验证的区别。不得以自加“再付费全量生成”门槛冒充原题明文要求，也不得将尚无证据的能力记为已验证。

本轮检验的是报告结构与证据适用性，不能对客户端记录作独立签章认证，也不能仅由机器证明真人标注、本人理解或服务商实际账单。原题不允许的数据文件仍不入 Git，不推送，不发邮件。
