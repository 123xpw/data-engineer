# 脱敏候选的当前源码重放验收

## 本轮开始前确定的通过标准

1. 在独立工作区复制已核验的原始数据、真实模型账本及回执，原私有候选的源码、配置、数据和账本保持不变。复用已锁定的 Python 依赖，不冒称新环境安装或冷启动。
2. 先检查所有待模型处理行均有本配置/提示/原文版本的有效缓存；有缺口立即停止。重放进程不持有真实模型 Key，并限制 Python 网络连接至本机回环地址；不能新增模型请求或账本条目。
3. 在源码冻结后重建 Q4 规范产物，与此前真实结果逐字核对，并用保存的真实响应、原始 CSV 和独立来源核验器逐行检查。规范文件和候选文件都必须有本次源码清单。
4. 通过现有全模块回归链：手算与边界、不同解析/算法参考、错误注入与变异、来源/金额/数量、独立命令及默认入口、故障后旧文件拒绝、真实 MySQL/TLS、Q5 设计和加分事实。最终全入口必须退出 0，且结果与独立核验版本一致。
5. 既有依赖安装、数据库生命周期和冻结 SQL 基准只在对应未变输入范围内复用；不改写旧回执。发生失败保留新失败记录，定位后再重跑受影响链。
6. 程序通过后再次运行完整提交门槛，人工标签、独立实际账单、公开日志完整性、最终版本/远端和本人复核尚未闭环的条件必须继续拒绝。不得以测试数量证明全部业务正确。
7. 重新扫描拟提交文件、Git 可达历史及本轮生成材料；原始 CSV、Parquet、私有配置/回执、账户观察不得纳入公开预览。新代码不自动继承旧脱敏检查。

## 本轮不认证的范围

本轮使用已有真实模型响应，不能证明最终源码完全无缓存的全量速度、当前服务可用性或新模型质量。引文字面核验不等于类别、翻译、否定、责任或严重度的真人正确率。Q5 是设计交付，没有部署压测。完整 AI 可见原文仍在本地保留，公开副本有明确遮盖；邮件要求的完整原文条件仍未满足。未授权推送或发送邮件。

## 结果填写原则

结果只链接实际新回执及其运行编号；记录复用证据的范围、失败与修复。不回填旧报告的源码摘要，不用文档写成通过来代替程序验收。

## 首次重放发现：Q2.4 验收器的证书前置依赖

Q4 缓存预检、规范重建与真实回执核验均通过；完整回归在 Q2.4 的手算连接处失败。独立调用复现 FileNotFoundError，新工作目录没有 `.venv/mysql-ca.pem`。原顺序在 `ensure_mysql()` 前使用 TLS 连接，依赖开发目录已有证书。

修复仅调整验收器：首先执行有证据的 MySQL/TLS 就绪检查，再进行冻结 SQL 与手算。验收标准是在本地证书缺失的独立目录启动后，自行完成 TLS 就绪、手算及后续回归；继续检查实际 TLS，不靠既有证书状态放行。业务 SQL、模型提示、真实响应及费用计算不变。受影响的验证源码指纹随本次修复重新冻结，先前失败回执保留。
