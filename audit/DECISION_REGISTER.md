## 面试前的本人验证方式

每个决定用自己的话讲清“需求—证据—选择—代价—失败条件”。至少独立手算一张含多商品、缺送达时间和取消订单的小表；用 2、2、77 秒重算舍入；解释无客户 ID 的记录为何不能合并成一个人；解释退货匹配为什么只是候选关系而非事实证明。

能复述文档不等于理解。建议本人实际改动一个小样例，先预测输出，再运行，并解释差异。尚未理解的部分如实补到 REFLECTION.md，不由 AI 代填“已理解”。

## 修复后的新增决策（2026-10-29，R1–R3）

- **禁止优化模式验收**：遗留断言在 `-O` 下会消失。先在统一入口拒绝，并逐步将关键判断换成显式异常；代价是验收不支持优化模式。面试应解释“测出了错误 SQL”与“优化模式拒绝执行”是两种不同证据，不能混为一个成功用例。
- **配置与存量数据绑定**：容器删除不代表数据卷为空。新随机密码只能用于新实例；缺原配置要失败，不能用删卷获得表面上的可重现性。R2 首次恢复失败又说明：端口冲突探针自身也要接受生命周期实验。
- **临时生成后发布清单**：单纯给旧文件补哈希仍可能把旧结果登记成新成功。必须让函数在空目录写齐文件，再发布；运行清单最后变为 passed。代价是旧文件可能保留，消费者必须检查本轮编号、状态与摘要。哈希无法证明业务语义，也不是面对恶意重写者的数字签名。
- **协议测试与业务实验分开**：人工夹具用于检验漏写、异常和控制流；真实 CSV/SQL 独立复算用于核对统计。两者不能互相冒充；函数返回成功也不能推出它确实交付了文件。

- **R4 分开安装、功能与完整交付证据**：相同锁文件的旧安装证明可以复用，但当前功能回归必须重跑；旧 R0 入口转发至统一门槛，不能按测试数量推断完成度。面试需解释为何已有范围通过而总入口仍返回 2，以及何时必须重新冷启动。

## Q2.3 卖家分析最小增量

- 继承 Q2.2 delivered 含运费 GMV，而订单数/取消率包含可归属所有状态：避免取消率恒为零。缺明细订单无法从当前数据确定卖家，不能猜测归属。
- 采用 customer_unique_id，商品先汇总卖家/订单、评价每订单选一条：避免订单键冒充客户、商品和评价连接放大权重。多卖家订单仍共享订单级评价和物流，不能当卖家责任证据。
- 最新评价作为确定性规则，公开最早与每单均分敏感性：原始 CSV 实测 72 位卖家评分受选择影响，不能声称规则得到业务方认证。
- 对数值相同但 JSON 类型错误也拒绝：计数应为整数，MySQL SUM 的 Decimal 不应自动变成字符串。
- 放弃强求捕获不可观测变异：同一 GMV 排序下，平台 TOP20 之前/之后算州排名可能数值相同。改测明确的全平台排名错误，承认测试预期也会错。
- 原失败进程未结束就修源码，守卫拒绝发布。后续前置失败立即停止，再冻结源码重跑；这一问题属于本轮执行安排，不能伪装成外部环境问题。
- 先交付独立 CLI 与单题入口，完整默认入口及统一门槛整合另行验收：明确最小增量的边界，不以局部数值正确推断完整项目可提交。

## Q4 与加分题新增决策（2026-10-30）

- **先完成工程，再真实实测**：无凭据时仍交付逐行分流、预算与评估工具，但输出 partial；引文存在不认证语义，合成 API 响应不是账单或人工标签。面试应能用葡语否定例说明结构测试的界限。
- **按行而非整批恢复**：小样本扩大、批大小改变会改变整批请求摘要，单靠批缓存可能重复付费。按来源行/原文/提示/服务价格版本恢复成功结果，未知计费不重发；累计账本不能因模型变化清零。预留与行标识同次持久化，避免中断窗口绕过恢复。
- **时间限制与吞吐分开**：隔离进程可终止慢滴流请求，不代表全量能在四十分钟处理完。真实小样本必须同时估计 token 费用和吞吐；当前串行方案可能需要新一轮有界并发验收，不能提高时限制造达标。
- **盲标先于解盲审查**：标签先填写类别、情感和可行动性，再看预测检查翻译/引文/严重度；仍承认同人解盲锚定偏差。没有真人标签就不出准确率，空分母为 null。
- **加分题数字不等于收益**：11,783.860 是特定 SQL 筛选的重复商品金额，不是新收入；217×五分钟仅是候选人工定位工作量情景。翻译 CSV 的 BOM 使新验收器首轮 KeyError，修解析器而不改事实数值，保留失败记录。


## 真实模型后的追加决策与反证

- 小样本4行真实失败并非免费：743/340 token 的调用费用上界保留。仅有JSON模式不能保证逐字引文，大小写/重音/冠词都会被生成器改写；严格最终校验仍保留。
- 不用整批失败迫使重付所有记录：按来源ID完整性检查后逐行挽救，错误行才补生成。批修复仍在44556/47809间串用Porto引文，最后隔离单条通过；不是因此宣称所有语义问题已消失。
- 最大三阶段生成而非无限重试：主批16、修复批4、单条隔离，每级一次，失败保持pending；未知计费不重发，单价、原文和提示版本参与缓存指纹。
- 单次执行时间与研发跨度分开：原自加“首次调用起40分钟”过度约束；修正后保留旧计时记录，实际主处理977.302249秒且有先期缓存，不把重放约6秒当成全冷性能。
- 新测试夹具缓存命中却期待deadline、验收器相对路径失败均被修复并重放；曾在测试失败后错误启动全量，已中断保留费用，不能在叙述中删去。
- 共享.env扩大了跨模块影响：原Docker会读入模型KEY。当前白名单临时文件只传四MYSQL项；真实新建/恢复容器以假模型变量确认隔离，同时保留原配置。仅有模型配置的新.env允许追加全新SQL凭据，旧卷/残缺SQL配置仍拒绝。
- 模型用量费用上界和实际账单分开：USD1.7664627为真实usage按官方峰时价计算，独立实际账单未核验。30条真人准确率仍未评估；模型confidence并非校准概率。

## Q2.3 性能轮：保留口径再改变物理计划

- 先冻结 0f40889 SQL，再限定候选只改变内连接顺序和事实块合并控制；运费、评价选择、分母、州内排名和 TOP20 不变。
