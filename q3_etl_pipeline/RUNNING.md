# Q3 运行与规则边界

独立命令：`python q3_etl_pipeline/pipeline.py`；输入为冻结 Retail CSV，输出三份 outputs/*.parquet、pipeline_log.txt、validation_metrics.json 与中文验证报告。Parquet 和逐条日志由原 .gitignore 忽略，不能提交。PyArrow 26.0.0 与其他依赖锁定，当前环境 Python 3.12.13。

销售为规则定义的正向商品毛交易：纯数字发票、正数量、正价；常规编码外允许 Q1 有实体商品描述支持的部分特殊码。原始码保留，仅分类时检查首尾空白；未知/手工/样品等隔离为 pending_product，不冒称已确认非商品。完整原始文件不删除，不默认去重。内部金额为精确整数千分单位，按题目要求导出 float；写入回读后核验类型和值。

RFM 基于上述毛购买，只有非空原始客户 ID 参加。国家以不同发票最多、字典序打破并列；基准日是原文件最后一个自然日。退货候选未经业务确认，不能把这些特征称为净留存；报告另给“全部候选若获确认”的敏感性。

全部 C 前缀进入退货日志；仅负数量、有客户、相同原始商品码与精确反向数量时匹配严格更早销售。最近优先，同时间取来源行较大者并标记歧义。每一销售行只消费一次，重复退货可回退更早未消费原单。买十退五不自动凑单，保留 NULL 与原因。价格不同时公开，匹配不是财务退款认证。

小样本手算通过后，真实 1,067,371 行预实验得到 1,037,021 条销售、5,852 客户、19,494 条取消、6,303 匹配候选；独立 CSV/Decimal/列表删除算法比较全部销售摘要、全部客户字段及全部候选，三份 Parquet 重跑字节一致。主环境单题 CLI 实测约 5.44 秒；这些是当前预实验，不是最终全项目验收或跨机器承诺。正式默认入口与新依赖冷环境证据其后已通过，当前以 reports/q3/acceptance_latest.json 的状态及源码摘要为准。

含 207 条“早期候选已被消费”、1 条 C 单非负数量；未匹配是信息/规则限制，不等于没有原单。覆盖率不是准确率。异常会保留诊断日志到本地忽略目录 .venv/q3-failures/；失败发布清单不接受旧结果。
