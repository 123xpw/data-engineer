# Q3 价格比较的未知状态：先定验收

基线为 `1b32c881ee3d3c605b1b10b7d2f8f39b3feb8072`。本轮仅澄清扩展字段 price_mismatch 的语义，不改变销售清洗、原单候选选择、容量约束、金额或 RFM 口径。

## 三态契约

| 匹配状态 | price_mismatch | 含义 |
|---|---|---|
| 没有匹配候选 | NULL | 无比较对象，价格是否不同未知 |
| 有候选且原始千分单位价格相同 | False | 与该候选的价格相同 |
| 有候选且原始千分单位价格不同 | True | 与该候选的价格不同 |

该比较仍针对算法选中的候选，不认证真实退款或原单归因。same_time_candidate_rows 仍表示原始同时间候选数量，不修改成“当前可用数”。

## 必须同时通过

1. 先用手造的同价、异价、缺客户、无候选、候选耗尽、同时间及异常取消记录建立三态预期。旧实现应被新用例检出，保存失败；不能只同时修改生产与参考后看二者相等。
2. 输出固定使用 pandas nullable boolean；未知恰好对应未匹配来源行。有匹配的记录必须为已知布尔，并由双方原始整数价格独立核对。将未知强填 False、将已匹配改成未知、颠倒同价/异价都必须拒绝。
3. Parquet 原生布尔类型、NULL 和 pandas nullable boolean 往返保留；同时覆盖全未知和空取消日志。NULL 不能写成字符串、0 或 False。
4. CSV/Decimal/列表删除参考保留独立实现：没有选中候选时不作价格比较，返回未知；选中后直接比较原始 Decimal 千分单位。逐行检查存储结果，不导入生产匹配或校验函数。
5. 冻结旧三表：销售与 RFM 的 Parquet 字节不变；退货日志除 price_mismatch 及其类型外，所有列、顺序和匹配选择不变。金额、6,303 个匹配及 217 个已知价格差异保持；未知数和同价数从实际数据核对，三类之和等于全部取消行。
6. 增加未知/同价/异价分母与字段文档；下游不能用补 False 或全部取消行为分母冒充已比较比例。已有加分题从原始 CSV 复算的价格差异仍须通过。
7. 冻结源码后重跑 Q3 全量独立参考、全部受影响回归及完整入口；模型只重放现有真实缓存、无新增请求。完整提交检查仍拒绝尚未闭环的人工、账单、日志及发布条件。
8. 最后检查文档链接、拟提交文件和可达历史；CSV、Parquet、凭据、私有账本不入 Git。不推送，保留失败与迭代提交。

## 范围与迁移

这是扩展字段的输出契约变更，旧调用方需显式处理 NULL；不能仅因旧代码与旧参考都写 False 就认定表达合理。并未因此解决部分退货、商品主数据确认、净 RFM、强杀恢复、跨平台或真人语义准确率。是否继续扩大验证由具体风险决定，不以测试数量声称不存在问题。
